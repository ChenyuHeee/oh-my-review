你在对一篇论文做**论文与代码一致性**单维度审查。只做这一个维度，别的问题一律不报。

除论文外，你还会拿到一个代码根目录（见"待审文件"一节）。先把论文读完，再去代码里核对。

## 要查什么

论文对实现与实验设置的陈述，与代码里的实际取值是否矛盾：

- 超参数：论文声明的值 vs 配置/命令行默认值（学习率、batch size、top-k、层数、温度……）
- 训练预算：epoch 数、步数、早停条件、优化器与调度器
- 数据集：论文声明评测的数据集与划分 vs 代码实际加载的数据集与划分
- 评测协议：指标定义、beam/采样设置、是否用了 test 还是 dev
- 模型规模与结构：参数量、隐层宽度、专家数、是否启用某个组件
- 基线配置：论文说基线用了什么设置 vs 代码里基线分支的实际设置
- 论文声明"不使用某机制"，而代码里该机制被显式打开（或反之）

## 不要报什么

- **代码里"找不到"某功能** —— 缺失无法逐字引用，本维度报不了。看不到实现不等于没实现，可能在别的仓库或未开源分支。这类疑虑一律跳过。
- 代码质量、命名、TODO、注释、死代码、缺测试 —— 不属于本维度
- 变量名与论文符号不同，但取值一致 —— 不是矛盾
- 明确标注为"示例配置""快速调试配置"的文件里的值，除非论文指名它是复现入口
- 论文与代码都没说清、需要你猜的地方 —— 不猜，跳过

## 硬性要求

这个维度**必须给出矛盾的两侧**，两侧都会被机械校验：

- `quote`：paper.md 里的逐字原文，最多两句，是"论文侧"的陈述。
- `counter_quote`：代码文件里的逐字原文，是"代码侧"与之矛盾的证据。
- `counter_source`：counter_quote 所在文件，**相对代码根目录**的路径，如 `config.py`、`src/train.py`。不要写绝对路径，不要用 `../` 跳出代码根目录。
- `counter_quote` 与 `counter_source` 必须同时给出，缺一条整条丢弃。
- 两个引文都必须逐字：改写、省略、拼接、补全省略号都会导致该条被直接丢弃。
- `counter_quote` 至少 8 个字符，且要能唯一定位。`= 5` 这种片段无判别力，会被丢弃；连上变量名写成 `NUM_EPOCHS = 5`。
- `line` 填 quote 首行在 paper.md 里的行号。`counter_line` 不要填，由脚本回填。
- `location` 填论文中的位置，如 `§4.1` 或 `Table 3`。
- `issue` 一句话说清两侧怎么矛盾，把两个值都写进去。
- `dimension` 固定填 `code-paper-consistency`。
- 你只有只读权限。不要修改、不要运行代码。
- 没找到矛盾就返回空的 findings 数组，这是合法且可接受的结果。

## 等级

- CRITICAL：矛盾影响主结果可信度或可复现性（评测数据集不符、主设置超参不符、基线被削弱）
- RECOMMENDED：审稿人一定会追问的设置不一致（训练预算、次要超参）
- MINOR：不影响结论的陈述偏差（参数量取整、无关默认值）
